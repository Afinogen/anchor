> ### 🇷🇺 Это форк [ZhFahim/anchor](https://github.com/ZhFahim/anchor) с полной русской локализацией
>
> Переведены веб-клиент, сообщения сервера и Android-приложение. Оригинальный
> проект только на английском и перевод не принял, поэтому он живёт здесь.
> Всё остальное — функции, схема данных, протокол синхронизации — код апстрима.

Anchor — это заметки и задачи, которые лежат на вашем сервере, а не в чужом
облаке. Правки работают без интернета (локальная база на устройстве) и
разъезжаются по устройствам, когда связь появляется.

## Чем отличается от оригинала

| Изменение | Зачем |
| --- | --- |
| **Русская локализация** веба, сервера и мобильного приложения | Ради этого форк и существует — см. [Локализация](#локализация) |
| Починен путь ассетов i18n в сборке сервера (`outDir: dist/src`) | Без этого `nestjs-i18n` внутри образа не находит переводы и отдаёт сырые ключи вида `auth.invalidCredentials` |
| Необязательный аргумент сборки `ALPINE_MIRROR` | `dl-cdn.alpinelinux.org` доступен не из любой сети, и `apk add` роняет сборку |
| Ссылка на скачивание APK на странице входа | Показывается, только если APK положен в `web/public/apk` |

Это весь диф: пять коммитов поверх апстрима `v0.16.0`. Ни новых функций, ни
изменений схемы, ни телеметрии.

Ошибки самого Anchor — [в апстрим](https://github.com/ZhFahim/anchor/issues),
претензии к переводу — [сюда](https://github.com/Afinogen/anchor/issues).

## Возможности

- **Локализация** — интерфейс, сообщения сервера и приложение на русском и английском *(только в форке)*
- **Редактор с форматированием** — жирный, курсив, подчёркивание, заголовки, списки, чек-боксы
- **Офлайн в первую очередь** — все правки идут в локальную базу и работают без сети
- **Общий доступ** — делиться заметкой с другими пользователями (чтение или правка)
- **История заметки** — смотреть прежние версии и возвращать любую из них
- **Теги** — свои метки с цветами
- **Вложения** — картинки и аудио в заметке
- **Фоны заметок** — сплошные цвета и узоры
- **Закрепление** — важные заметки наверху списка
- **Архив** — убрать с глаз, не удаляя
- **Поиск** — по заголовку и содержимому, локально
- **Корзина** — мягкое удаление с периодом восстановления
- **Автосинхронизация** — изменения разъезжаются по устройствам при появлении сети
- **Импорт и экспорт** — выгрузка всей библиотеки, загрузка обратно, импорт из Google Keep
- **Виджет на рабочий стол** — быстрый доступ с домашнего экрана Android
- **Панель администратора** — пользователи, управление регистрацией, статистика
- **Вход через OIDC** — Pocket ID, Authelia, Keycloak и другие провайдеры

## Локализация

| Платформа | Языки | Как выбирается язык |
| --- | --- | --- |
| Веб | English, Русский | При первом запуске — язык браузера, дальше **Настройки → Язык**; выбор запоминается в браузере |
| Сервер (ошибки, письма, ответы API) | English, Русский | `?lang=ru`, заголовок `X-Lang: ru` или `Accept-Language`; фолбэк — английский |
| Android-приложение | English, Русский | Язык системы либо кнопка EN/RU на экране входа и настройки сервера |

Где лежат строки:

- **веб** — `web/lib/i18n/locales/{en,ru}.ts`, хук `useTranslation()`.
  Тип `TranslationKey` выводится из английского словаря, поэтому забытый ключ —
  это **ошибка сборки**, а не пустая надпись у пользователя.
- **сервер** — `nestjs-i18n`, JSON по неймспейсам в `server/src/i18n/{en,ru}/`
  (`auth`, `notes`, `tags`, `admin`, `import`, `oidc`, `settings`).
- **мобильное** — Flutter `gen-l10n`, ARB-файлы `mobile/lib/l10n/app_{en,ru}.arb`,
  обращение через `context.l10n.<ключ>`.

Как добавить свой язык: скопировать английский словарь во всех трёх местах,
зарегистрировать локаль в `web/lib/i18n/config.ts` и в `mobile/lib/l10n/`, затем
выполнить `cd web && pnpm build` — сборка перечислит все пропущенные ключи.

Чистым функциям-хелперам локаль передаётся **необязательным** параметром с
английским фолбэком: тесты апстрима проходят без правок, а мержи остаются
маленькими.

**Ещё не переведено:** зона загрузки вложений в веб-клиенте
(`web/features/notes/components/attachments/attachment-upload-zone.tsx`).

## Установка через Docker

> Готового образа у форка нет. `ghcr.io/zhfahim/anchor` — это образ апстрима,
> он **без перевода**; собирайте из исходников этой ветки.

1. **Склонировать форк и собрать:**

   ```bash
   git clone -b i18n https://github.com/Afinogen/anchor.git
   cd anchor
   docker compose up -d
   ```

   `docker-compose.yml` соберёт образ из исходников и поднимет его на порту 3000
   вместе со встроенным PostgreSQL в томе `anchor_data`.

2. **Если сборка падает на `apk add`** — из вашей сети недоступен CDN Alpine.
   Указать зеркало:

   ```bash
   docker build --build-arg ALPINE_MIRROR=https://mirror.yandex.ru/mirrors/alpine \
     -t anchor:0.16.0-i18n .
   ```

3. **Открыть приложение:** http://localhost:3000

4. **(Необязательно) Настроить окружение.** Переменные добавляются в секцию
   `environment` в compose-файле. Значений по умолчанию хватает большинству.

   | Переменная | Обязательна | По умолчанию | Что делает |
   |----------|----------|---------|-------------|
   | `APP_URL` | нет | `http://localhost:3000` | Базовый адрес, по которому отдаётся Anchor |
   | `JWT_SECRET` | нет | (генерируется) | Секрет токенов авторизации, минимум 16 символов |
   | `DATA_DIR` | нет | `/data` | Корневой каталог для загруженных файлов |
   | `CORS_ORIGINS` | нет | (разрешено всё) | Список источников CORS через запятую |
   | `PG_HOST` | нет | (пусто) | Внешний Postgres; пусто — встроенный |
   | `PG_PORT` | нет | `5432` | Порт Postgres |
   | `PG_USER` | нет | `anchor` | Пользователь БД |
   | `PG_PASSWORD` | нет | `password` | Пароль БД |
   | `PG_DATABASE` | нет | `anchor` | Имя базы |
   | `USER_SIGNUP` | нет | (не задана) | Режим регистрации: `disabled`, `enabled`, `review`. Если не задана — управляется из админки |
   | `OIDC_ENABLED` | нет | — | Включить вход через OIDC |
   | `OIDC_PROVIDER_NAME` | нет | `"OIDC Provider"` | Подпись на кнопке входа |
   | `OIDC_ISSUER_URL` | при OIDC | — | Базовый адрес провайдера |
   | `OIDC_CLIENT_ID` | при OIDC | — | Идентификатор клиента |
   | `OIDC_CLIENT_SECRET` | нет | — | Секрет клиента; для публичного клиента (PKCE) не нужен |
   | `DISABLE_INTERNAL_AUTH` | нет | `false` | Спрятать форму логина, оставив только OIDC |

### Как проверить перевод

Локализация ломается только в собранном образе, в dev-режиме всё зелёное —
поэтому проверять надо на контейнере:

```bash
curl -H "Accept-Language: ru" http://localhost:3000/api/... # ждём русский текст, а не ключи вида auth.invalidCredentials
```

## Мобильное приложение

В [релизах апстрима](https://github.com/ZhFahim/anchor/releases) лежит английская
сборка. Русскую надо собрать из этой ветки:

```bash
cd mobile
flutter build apk --release            # или --split-per-abi, чтобы файлы были меньше
```

Результат положить в `web/public/apk/` (в контейнере это `/app/web/public/apk`) —
на странице входа появится ссылка на `anchor-arm64-v8a.apk`.

> **Сервер и приложение обновляются вместе.** С версии 0.16 они обязаны
> совпадать по `X-Anchor-Protocol` (сейчас `3`); при расхождении сервер отвечает
> HTTP 426 и синхронизация встаёт.

## Вход через OIDC

Anchor умеет OpenID Connect — удобно, когда пользователей несколько и пароли
хочется держать в одном месте.

### Что поддерживается

- Стандартные провайдеры: Pocket ID, Authelia, Authentik, Keycloak и прочие
- Настройка переменными окружения либо через админку
- Режим «только OIDC»: локальный вход по паролю отключается
- Публичные клиенты (PKCE, без секрета)
- Автосоздание пользователя при первом входе (если регистрация не запрещена)
- Автопривязка к существующему пользователю по email

### Настройка

#### Мобильное приложение и публичный клиент

Чтобы OIDC работал в приложении, заведите Anchor как **публичный клиент**
(PKCE, без секрета) и добавьте у провайдера redirect URI:

```
anchor://oidc/callback
```

#### Callback-адрес для веба

У провайдера нужно прописать адрес возврата:

```
{APP_URL}/api/auth/oidc/callback
```

Например, если Anchor живёт на `https://notes.example.com`, то:

```
https://notes.example.com/api/auth/oidc/callback
```

#### Переменные окружения

Пример для Pocket ID в `docker-compose.yml`:

```yaml
services:
  anchor:
    build: .
    environment:
      - OIDC_ENABLED=true
      - OIDC_PROVIDER_NAME=Pocket ID
      - OIDC_ISSUER_URL=https://pocketid.example.com
      - OIDC_CLIENT_ID=your-client-id
      - OIDC_CLIENT_SECRET=your-client-secret # для публичного клиента не нужен
      - DISABLE_INTERNAL_AUTH=false
      - APP_URL=https://notes.example.com
```

#### Через админку

Если три обязательные переменные заданы не все, OIDC настраивается в панели
администратора: Настройки → OIDC Authentication.

## Диагностика и сбор логов

Anchor не собирает никаких данных. Если нужно сообщить об ошибке, лог снимается
вручную и прикладывается к сообщению.

**Мобильное приложение**

1. Воспроизвести проблему.
2. Настройки → Просмотр логов.
3. Кнопка **Экспорт** внизу, приложить полученный `.log` к отчёту.

> Чувствительные значения вычищаются до записи в файл: заголовки авторизации,
> пароли, токены, refresh-токены, секреты и адреса почты всегда заменяются на `***`.

Логи хранятся только на устройстве (кольцевые, до ~2 МБ).

## Синхронизация с апстримом

Форк догоняет оригинал **мержем**, не ребейзом — история остаётся читаемой:

```bash
git fetch upstream && git merge upstream/main
```

Перед пушем прогнать всё: `flutter analyze` и `flutter test` в `mobile/`,
`pnpm build && pnpm test` в `server/`, `pnpm exec tsc --noEmit`, `pnpm test --run`
и `pnpm build` в `web/`. И проверить грепом вызовы `t(`, которые конфликт мог
решить в пользу апстрима.

## Как поучаствовать

Новые языки и правки перевода — сюда. Всё остальное лучше нести в апстрим, там
это достанется всем пользователям.

1. Сделать форк репозитория.
2. Завести ветку:
   ```bash
   git checkout -b feature/your-feature
   ```
3. Внести правки.
4. Убедиться, что собирается и проходит линтер:
   - веб: `cd web && pnpm build && pnpm check`
   - сервер: `cd server && pnpm build && pnpm check`
5. Закоммитить и открыть Pull Request.

Линтер и форматирование проверяются в CI и pre-commit-хуком
(`.githooks/pre-commit`). Хук включается сам при `pnpm install` в `web` или
`server`, вручную — `git config core.hooksPath .githooks`. Починить замечания:
`pnpm check:fix` в нужном проекте.
